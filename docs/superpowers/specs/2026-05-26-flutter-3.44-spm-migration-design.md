## Problem

O projeto RARO estava em **Flutter 3.41.9** com iOS gerenciado por **CocoaPods** (Podfile + `pod install`). A spec `api-contract-shared` (entregue em 2026-05-26, session 0002) deixou exatamente **um gate pendente**:

- `flutter build ios --no-codesign --debug` não compilou Swift de verdade porque CocoaPods não está instalado no Mac de desenvolvimento.

O caminho tradicional seria instalar CocoaPods via Homebrew. Mas pesquisa moderna (Context7 + WebSearch em 2026-05-26) revelou que:

1. **CocoaPods está em manutenção** e o registro CDN vira **read-only em 2026-12-02** (6 meses).
2. **Firebase parou de publicar em CocoaPods em outubro/2026**. Atualizar Firebase no futuro **exige** SPM.
3. **Flutter 3.44.0 (released 2026-05-12, 14 dias atrás)** torna **Swift Package Manager o default oficial** para iOS/macOS.
4. **Build iOS fica ~10-20% mais rápido** com SPM, sem dependência de Ruby/gem.
5. **Apple endossa** SPM; CocoaPods é projeto comunitário com data de validade conhecida.

Esta spec faz a migração **completa e cirúrgica** seguindo o princípio MVP do projeto (R$1.800, sem sobre-engenharia):

- Upgrade SDK Flutter para latest stable 3.44.x (usuário já executou — Flutter 3.44.0 + Dart 3.12.0 confirmado em 2026-05-26)
- Migrar iOS de CocoaPods para SPM (`pod deintegrate` manual, remoção de `Podfile`/`Podfile.lock`/`Pods/`, limpar referências em `project.pbxproj`)
- Bump iOS deployment target 14.0 → 15.0 (perde iPhone 6s/7/8/SE 1ª ger — autorizado pelo usuário em 2026-05-26)
- Habilitar SPM via `flutter config --enable-swift-package-manager`
- Atualizar Blueprint (Seções 2.1, 7, 9) + CLAUDE.md (Seção 2, 3) + criar ADR-014
- Aceitar Podfile híbrido auto-gerado se `permission_handler`/`share_plus`/`device_info_plus` ainda não suportarem SPM (tech-debt resiliente, documentado)

**Não esta spec**: migração para `material_ui`/`cupertino_ui` packages (ainda não publicados oficialmente; deprecation warning aceito), upgrade Riverpod/go_router/Firebase major (Surgical Changes), GitHub Actions CI (overkill MVP).

### Componente 3 — Deintegrar CocoaPods (manual, sem `pod`)

`pod` não está instalado no Mac. Deintegração manual segura:

```bash
cd apps/mobile/ios
# Podfile já deletado pelo usuário. Garantir Podfile.lock + Pods + symlinks também:
rm -f Podfile Podfile.lock
rm -rf Pods/ .symlinks/
```

**Limpar referências CocoaPods de `Runner.xcodeproj/project.pbxproj`:**

Edit cirúrgico — remover linhas/blocos contendo:
- `[CP]` (CocoaPods script phase prefix, e.g. `[CP] Check Pods Manifest.lock`, `[CP] Embed Pods Frameworks`)
- `Pods-Runner` (target reference)
- `${PODS_ROOT}` (path variable)
- `Pods-Runner.xcconfig` (config include)

Estratégia: usar `sed`/`grep -v` ou `Edit` tool blocos definidos por linha. Cada bloco bem delimitado (script phase tem `isa = PBXShellScriptBuildPhase` + `shellScript` + ID hex).

**Verificação:**
```bash
grep -c "\[CP\]\|Pods-Runner\|PODS_ROOT" apps/mobile/ios/Runner.xcodeproj/project.pbxproj
# Esperado: 0
```

## Como evoluir o contrato (governança)

1. **Bump Flutter minor (3.44 → 3.45)**: PR normal, sem ADR. Valida com `flutter analyze + test + build apk + build ios` antes de merge.
2. **Bump Flutter major (3.x → 4.x)**: ADR novo obrigatório. Spec dedicada.
3. **Bump iOS deployment target (15 → 16)**: ADR novo (perde mais devices). Spec dedicada.
4. **Migrar para `material_ui`/`cupertino_ui` packages quando lançados**: ADR novo + spec dedicada. Provavelmente bundled com upgrade Flutter futuro.
5. **Plugin específico não-SPM migrado upstream**: PR normal removendo Podfile híbrido residual. Sem ADR.
