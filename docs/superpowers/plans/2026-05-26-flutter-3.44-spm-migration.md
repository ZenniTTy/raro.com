# flutter-3.44-spm-migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrar plataforma iOS do RARO de CocoaPods para Swift Package Manager, com upgrade Flutter 3.41→3.44 e iOS deployment target 14→15, fechando o gate `flutter build ios` pendente da spec anterior.

**Architecture:** Mudança cirúrgica de plataforma. (1) Captura mudanças intermediárias já presentes no workspace (Podfile deletado + pubspec.lock atualizado) em commit limpo. (2) Habilita SPM globalmente via flutter config. (3) Limpa referências CocoaPods do project.pbxproj (manual, sem `pod deintegrate`). (4) Bump iOS deployment target em 2 arquivos. (5) Atualiza pubspec, tenta voltar pigeon 26.3.4 com fallback automático. (6) Cria ADR-014 + atualiza Blueprint + CLAUDE.md + CHANGELOG + session log. (7) Valida builds Android (sem regressão) e iOS (gate crítico). Cada task termina com harness completo verde antes do commit.

**Tech Stack:** Flutter 3.44.x stable channel + Dart 3.12.x (usuário já upgradou em 2026-05-26), Swift Package Manager (Apple-native, default em Flutter 3.44), Xcode 15+, iOS 15.0+ deployment target, pigeon ^26.3.4 (tentativa, fallback 26.3.2), theme_tailor ^3.1.3, monorepo Bun + Turborepo, lefthook + commitlint.

**Reference:** spec `docs/superpowers/specs/2026-05-26-flutter-3.44-spm-migration-design.md` (Approved 2026-05-26).

## 7 execution rules (sempre aplicar)

1. **Surgical changes** — só toque no que a task pede. Sem refactor de passagem. Sem bumps "de oportunidade" de outras deps.
2. **Sem comentários** em código de produção. Nomes explicam WHAT.
3. **Imports absolutos** via `package:raro_mobile/...` ou `package:raro_shared/raro_shared.dart`. Sem `../../../`.

5. **Strict lints** — `flutter analyze` zero issues após cada arquivo. Deprecation warnings de `material.dart` aceitáveis (esperados pós-Flutter 3.44).
6. **Strings de UI em `.arb`** — sem inline. Esta spec não cria UI.
7. **Conventional Commits** — scope-enum em `commitlint.config.cjs`. Subject lowercase. **Nunca `--no-verify`**.

```markdown
# 0014 — Flutter 3.44 + Swift Package Manager + iOS 15

- **Data:** 2026-05-26
- **Status:** Accepted
- **Spec:** docs/superpowers/specs/2026-05-26-flutter-3.44-spm-migration-design.md
- **Supersedes:** parcialmente ADR-0001 (Flutter version pin original `>=3.41.0`, agora `>=3.44.0`)

## Contexto

A spec `api-contract-shared` (entregue em 2026-05-26, session 0002) deixou um gate pendente: `flutter build ios --no-codesign --debug` não compilava Swift porque CocoaPods não estava instalado no Mac de desenvolvimento. Em vez de instalar CocoaPods (caminho tradicional mas em manutenção), pesquisa moderna em 2026-05-26 (Context7 + WebSearch + pub.dev API) revelou:

1. **CocoaPods está em manutenção** — registro CDN vira **read-only em 2026-12-02** (~6 meses).
2. **Firebase parou de publicar em CocoaPods em outubro/2026**. Atualizar Firebase no futuro **exige** SPM.
3. **Flutter 3.44.0** (released 2026-05-12) torna **Swift Package Manager o default oficial** para iOS/macOS.
4. **Build iOS fica 10-20% mais rápido** com SPM, sem dependência de Ruby/gem/pod.
5. **Apple endossa** SPM nativamente.

## Decisão

Migração tríplice integrada em uma única decisão (sempre vão juntas):

1. **Flutter 3.41.9 → 3.44.x** (latest stable). Dart 3.11 → 3.12. Constraint pubspec: `flutter: ">=3.44.0"`, `sdk: ">=3.12.0 <4.0.0"`.
2. **CocoaPods → Swift Package Manager**. Habilitado via `flutter config --enable-swift-package-manager`. Removidos `apps/mobile/ios/Podfile`, `Podfile.lock`, `Pods/`, e referências `[CP]`/`Pods-Runner`/`PODS_ROOT` de `Runner.xcodeproj/project.pbxproj`.
3. **iOS deployment target 14.0 → 15.0**. Apple SPM requirement. Atualizado em `project.pbxproj` (≥3 ocorrências) e `Flutter/AppFrameworkInfo.plist`.

## Consequências

**Positivas:**
- Build iOS ~10-20% mais rápido (validado por benchmarks comunidade Flutter)
- Eliminada dependência de Ruby 2.6 do sistema (deprecated) + `gem install cocoapods`
- Onboarding novo dev iOS reduzido (sem `brew install cocoapods` + `pod install`)
- Preparado para atualizações Firebase pós-outubro/2026 (Firebase só publica em SPM agora)
- Alinhamento com direção oficial Apple
- Eliminado risco de CocoaPods CDN read-only em dez/2026

**Negativas:**
- Perde suporte a iPhone 6s/7/8/SE 1ª geração (presos em iOS 14.x — ~5-8% iPhones ativos globalmente, maior no BR)
- `package:flutter/material.dart` agora emite deprecation warning (Material/Cupertino vão virar packages standalone `material_ui`/`cupertino_ui` futuramente — espera-se publicação oficial)
- Possível Podfile híbrido auto-gerado pelo Flutter se plugin não suportar SPM (permission_handler PR #1440 não merged, share_plus/device_info_plus issue #3152 em rollout) — aceito como tech-debt resiliente, documentado em CHANGELOG

**Neutras:**
- Pigeon pode voltar a `^26.3.4` se Dart 3.12 (analyzer 10.x) resolver o conflito que travou em `^26.3.2` na spec anterior — atualizado em runtime pelo plan; se não resolver, mantém 26.3.2 sem regressão.
- Renovate/dependabot fora de escopo desta ADR.

## Alternativas consideradas

- **Ficar em Flutter 3.41 + CocoaPods** — rejeitado. CocoaPods read-only em dez/2026 + Firebase parou de publicar lá em out/2026. Manter seria tech-debt com data de validade conhecida.
- **Wait-and-see Flutter 3.44.2+ para amadurecer** — rejeitado. Projeto está em fase inicial (MVP, ~30 commits), branch isolada, sem usuários produção. Momento ideal para upgrades de plataforma.
- **Manter iOS 14 + SPM parcial** — rejeitado. SPM moderno (Flutter 3.44 default) exige iOS 15+. Não há benefício em meio-caminho.
- **Migrar para material_ui/cupertino_ui packages agora** — rejeitado. Esses packages ainda não foram publicados oficialmente em 2026-05-26. Esperar release.
```
